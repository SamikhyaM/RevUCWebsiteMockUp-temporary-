Make your own layer in code

// 1. an offscreen strip: 2000 units wide, 180 tall (3 pixels per unit)
var s = mk(2000, 180), c = s.x;

// 2. paint with units. The ground line is y = 138, the road starts at y = 148
wall(c, 100, 138 - 70, 60, 70, '#b5503a');                     // brick block
foliage(c, 40, 120, 50, 18, ['#4f8a3a', '#7aa83a'], ['#ffd27a']); // bush + flowers
tier(c, 300, 138, 24, 60, '#6e3a8c');                           // tower segment
cap(c, 300, 78, 24, 14, '#6e3a8c');                             // pointed top

// 3. draw the visible slice every frame (f = parallax speed)
ctx.drawImage(s.c, cam * f * 3, 0, viewW * 3, 540, 0, 0, viewW, 180);

Canvas shapes vs. image files

  • Loading. Painted-in-code layers need no download but take about a second to paint at startup. Image files need a download first, then decode quickly. Wide full-resolution strips can be a few MB each, so use WebP for skies and PNG/WebP for transparent layers.
  • Preloading. Yes: create an Image, set src, await img.decode(), then ctx.drawImage(img, …). Load all layers with Promise.all and show a loading screen until they finish. createImageBitmap(img) makes later draws a bit faster.
  • Same drawing code. A loaded image drops into the layer list the same way a painted canvas does, because both work with drawImage. That is how the upload button above works.
  • Published pages. They can’t fetch remote images. Images have to be embedded as data: URLs inside the HTML file (about 33% bigger, 16 MB file limit). If you host the site yourself, normal image files with img.decode() are the better route.
  • Quality. Images let you paint layers in Procreate, Photoshop or Krita and get real brush texture. Code-made layers are better for tiny files and quick edits.
